# API Reference

Makio MeshLine is built with creative coding requirements in mind: **performance**, **customization**, and **simplicity**, so you can focus on your creativity.

It's built for the future, using `TSL` and is compatible only with the new `WebGPURenderer` (But both backend: `WebGPU`/`WebGL2`)

## [MeshLine](/meshline)

High-level façade – **the class you will use 99 % of the time**. It can build either a camera-facing screen stroke or a camera-independent world-space surface.

```ts
new MeshLine(options?: MeshLineOptions)
```

For convenience, use the fluent API below:

```ts
new MeshLine().color(0xff0000).gradientColor(0xff00ff) // etc.
```

Use `.surface( options )` when the path represents a road, track, or lit ribbon. See [World-Space Surfaces](/surface).

## [MeshLineGeometry](/meshline-geometry)

Low-level geometry builder – it's created internally by `MeshLine`; reach for it when you need to **update or add extra buffer attributes**.

```ts
new MeshLineGeometry(options?: MeshLineGeometryOptions)
```

## [MeshLineNodeMaterial](/meshline-material)

Specialised `NodeMaterial` that understands the vertex attributes generated by `MeshLineGeometry` and renders them with:

* Constant CSS-pixel thickness or scene-space projected thickness
* Optional gradients, textures, dashes, etc..
* Always-on bounded miter join (`miterLimit` tunes the cap) — optional sharp-bend subdivision is available for static paths
* Optional TSL hooks to customize the vertex & fragment easily

```ts
new MeshLineNodeMaterial(parameters?: MeshLineNodeMaterialParameters)
```

## [MeshLineSurfaceGeometry and MeshLineSurfaceNodeMaterial](/surface)

World-space geometry and PBR material used by `new MeshLine().surface()`. The geometry creates camera-independent frames, distance-based UVs, normals, tangents, true bevel/round joins, caps, and explicit reversal splits for roads and ribbons.

```ts
new MeshLine()
  .lines( roadPoints )
  .lineWidth( 4 )
  .surface( { frame: 'transport', uvMode: 'distance', uvScale: 5 } )
  .join( { type: 'round', segments: 8 } )
  .cap( { type: 'round', segments: 8 } )
  .build()
```

Prefer the `MeshLine` façade unless you specifically need to compose the low-level surface geometry and material yourself.

## [MeshLineCullingSystem](/gpu-culling)

Optional native-WebGPU chunk culling for very large opaque packed lines and road surfaces. Import it from `makio-meshline/gpu-culling` (Three.js r183+) so the regular WebGPU/WebGL2 entry point keeps its wider compatibility range.

```ts
const culling = MeshLineCullingSystem.attach(renderer, scene, { mode: 'auto' })
culling.add(line)
```

The system compacts visible indices into one indirect draw and fails open for unsupported backends, passes, materials, or bounds.

## [MeshLineGPUPath](/gpu-path)

Experimental native-WebGPU point-centric renderer for one very large static open screen line. Import it from `makio-meshline/gpu-path` (Three.js r183+). It stores source points once, optionally applies a guaranteed discrete local-space dyadic tolerance, and renders one non-indexed indirect draw. Advanced mode emits true bevel/round joins, square/round caps, explicit reversal splits, and width-padded homogeneous clipping.

Pass `{ variableTopology: true }` as the second constructor argument to opt the otherwise-fast `miter + butt` signature into shared miter triangles and a true over-limit bevel. Adapter storage limits are validated before staging; oversized topology fails back instead of producing a WebGPU validation error.

The wrapper always retains a complete CPU `MeshLine` and selects it for unsupported backends, multi-line/closed/surface/shadow/XR profiles, or failures. The fallback preserves full source detail but uses the regular fixed-strip miter/butt visuals. Advanced GPU topology remains full detail because local-space LOD cannot safely remove camera-dependent projected cusps.

## [MeshLinePicker & MeshLinePickerHelper](/picking)

GPU pixel-picker that identifies which line / instance is under the cursor — works with GPU-positioned, instanced, animated, and hook-driven lines because it reads what was rendered, not a CPU proxy.

```ts
new MeshLinePicker(renderer, scene, camera, options?: MeshLinePickerOptions)
```

`MeshLinePickerHelper` is a Three.js-style visual helper (in the spirit of `BoxHelper` / `SkeletonHelper`) that overlays the picker's wide hit-zones on your scene, painted with a distinct hue per instance — useful for verifying coverage and debugging missed hits.

```ts
const helper = new MeshLinePickerHelper(picker, { opacity: 0.45 })
scene.add(helper)
// in your render loop:
helper.update()
```

See the dedicated [picking page](/picking) for the full API.

## Implementation Notes

* Only the uniforms / attributes needed are created & uploaded to the GPU.
* Many hooks are available for customizing line behavior and rendering
* Instancing + gpu position will allow you to render thousands of lines like a breeze
* You can also use batching for performant CPU-controlled animation or static lines 
* The surface profile uses ordinary world-space mesh geometry for roads, tracks, and lit ribbons
* Optional native-WebGPU chunk culling is available for large opaque packed paths
* No runtime dependencies beyond `three`
